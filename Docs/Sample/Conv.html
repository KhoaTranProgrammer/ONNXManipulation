Understanding Conv.json

This sample describes a small ONMA graph containing one two-dimensional convolution. The graph has one input tensor, one constant weight tensor, and one output tensor. It can be passed to ONMACreateGraph.py to create an ONNX model.

Graph overview

  1. Provide input tensor X with shape [1, 1, 4, 4].
  2. Apply the convolution node Conv_Node using constant weights W.
  3. Produce output tensor Y with shape [1, 1, 3, 3].

Input and output tensors

Tensor shapes use ONNX's NCHW order: batch, channels, height, width.

TensorShapeInterpretationData type
X[1, 1, 4, 4]One batch containing one 4 × 4 input channel.float32
Y[1, 1, 3, 3]One batch containing one 3 × 3 output channel.float32

The input entry declares its name, shape, and type; it does not provide runtime input values. Values for X must be supplied when the generated model is run.

Weight initializer

W is a constant tensor with shape [1, 1, 2, 2]: one output channel, one input channel, and a 2 × 2 kernel. All four kernel values are 0.25. There is no bias initializer or bias input. 

W[0, 0] = [[0.25, 0.25],
           [0.25, 0.25]]

For each output position, this kernel multiplies the corresponding 2 × 2 input region by 0.25 and sums the four results. Thus each output is the average of that input region.

Why is the output 3 × 3?

With input height and width 4, kernel size 2, stride 1, and no padding, each spatial output dimension is floor((4 - 2) / 1) + 1 = 3. The batch and output-channel dimensions are both 1, so Y has shape [1, 1, 3, 3].

Expected behavior: the model computes nine overlapping 2 × 2 averages from X. Numeric output values depend on the runtime values supplied for X.
